# gitgit 스킬

## 흐름 (질문 1번, 그 이상 없음)

### 1. 상태 확인 (조용히)

`git status`로 상태 파악. 문제 있으면 바로 안내하고 종료:

- git 레포 아님 → "현재 폴더는 git 레포가 아닙니다."
- remote 없음 → "연결된 GitHub 레포가 없습니다. `git remote add origin <URL>` 먼저 해주세요."
- 변경사항 없음 → "커밋할 변경사항이 없습니다."

### 2. 커밋 메시지 확인 (AskUserQuestion 도구 사용)

변경 파일 요약 + 자동 생성 커밋 메시지 제시. **텍스트로 묻지 말고 반드시 `AskUserQuestion` 도구 호출**:

- 질문 본문: `"이 메시지로 커밋할까요?\n\n[자동생성 메시지]"`
- 옵션 1: `"진행"` (Recommended)
- 옵션 2: `"취소"`

응답 처리:
- **"진행"** → 자동 생성 메시지 그대로 실행
- **"취소"** → 스킬 종료 ("취소되었습니다." 안내)
- **"Other"** (사용자가 직접 입력한 커스텀 메시지) → 그 메시지로 실행

이 방식으로 사용자는 **클릭 한 번**으로 확정 가능 (타이핑 불필요).

**추가 확인 질문 절대 금지.** "진짜 해도 돼요?", "확실합니까?" 같은 재확인 없이 바로 실행.

### 3. 실행

```bash
git add .
git commit -m "[커밋 메시지]"
git push
```

upstream 없으면 `git push -u origin [현재 브랜치명]`으로 자동 처리.

### 4. 완료 메시지

```
완료. [브랜치명] → GitHub push됨.
```

## 에러 처리

| 상황 | 처리 |
|------|------|
| push rejected (원격에 새 커밋 있음) | "원격에 변경사항이 있어요. `git pull` 먼저 해주세요." |
| SSH 인증 실패 | "SSH 인증 실패. `ssh -T git@github.com` 으로 연결 확인해 주세요." |
| conflict | "충돌이 있어요. 파일 수정 후 다시 `/gitgit` 해주세요." |

force push는 사용자가 요청해도 먼저 위험성 설명 후 동의 받고 실행.
