## WBS 번호 체계

```
[대분류].[그룹번호][그룹내순번]_이름\

예)  1   .  1       0           _Onboarding
     ↑      ↑       ↑
   Work   그룹1.1  0번(메인)
```

| 자리 | 의미 | 예시 |
|------|------|------|
| 첫째 자리 | 대분류 | 1=Work, 2=Personal, 3=Dev, 4=Resources |
| 둘째 자리 | 그룹 | 1.1x=온보딩계열, 1.2x=S-Oil계열 |
| 셋째 자리 | 그룹 내 순번 | 0=메인(그룹 대표), 1, 2, 3… |

> 자식 폴더는 부모 번호를 그대로 이어받아 점(`.`) 뒤에 순번 붙임: `1.10` 자식 → `1.10.0`, `1.10.1`…

## 영역 구분

자료가 저장되는 위치는 두 영역으로 나뉨:

| 영역 | 누가 씀 | 위치 | 용도 |
|------|---------|------|------|
| **사용자 영역** | 사람 (정별) | `C:\Users\정별\0_~4_*\` | 작업 산출물, 문서, 메모 |
| **Claude 자동 영역** | Claude Code | `C:\Users\정별\.claude\` | 메모리, 세션, 플랜, 파일 히스토리 |

위 WBS 트리는 **사용자 영역**만 다룸.

## 폴더 네이밍 규칙

| 규칙 | 내용 |
|------|------|
| 번호 prefix | WBS 번호를 앞에 붙임 (`1.20_S-oil_Projects`) |
| 구분자 | 언더스코어 `_` 사용, 공백 금지 |
| 한글 허용 | leaf 폴더는 한글 사용 가능 |
| 쉼표 허용 | 열거가 자연스러운 경우 쉼표(`,`) 사용 가능 (예: `기능위치,_설비ID`) |
| 보관 폴더 | 비활성 항목은 해당 레벨의 `보관_Archive` 폴더로 이동 |

## 파일 네이밍 규칙

### 기본 구조
```
[큰개념]_[중간개념]_[발표자]_[버전]_[날짜].확장자
```

- **순서**: 큰 개념 → 작은 개념 (범위가 좁아지는 방향)
- **길이**: 세그먼트 최대 4개. 불필요한 중간 개념은 생략
- **구분자**: 언더스코어 `_`, 공백 사용 금지
- **`[발표자]` 슬롯**: 회의록·교육문서 등은 실제 발표자명. 발표자가 없는 일반 파일(엑셀 용어집 등)은 담당자명(`정별`)을 넣거나 생략

### 버전 규칙

| 상태 | 버전 형식 | 예시 |
|------|-----------|------|
| 작업 중 (초안) | `v0.1` → `v0.2` → … | `v0.9` → `v0.10` → `v0.11` |
| 최종 산출물 | `v1.0` | 검토 완료 후 제출 시 |

> 버전은 소수점 방식으로 연속 증가. `v0.9` 다음은 `v0.10` (v1.0으로 올리지 않음)

### 날짜 형식
- `YYYYMMDD` 형식, 파일명 맨 끝에 위치
- 예: `_20260520`

### 예시
```
mMDM_용어집_정별_v0.1_20260101.xlsx        ← 초안 (담당자명)
mMDM_온보딩_김부장_v0.1_20260301.docx      ← 회의록 (발표자명)
한화에너지_데이터표준화_v0.11_20260301.xlsx ← 발표자 없음 (3 세그먼트로 생략)
mMDM_용어집_정별_v1.0_20260520.xlsx        ← 최종 산출물
```

## 운영 원칙

1. **바탕화면에는 단축키만** — 실제 파일/폴더는 WBS 구조 안에만 존재
2. **새 그룹 추가** → 기존 마지막 그룹번호 다음 `N0`으로 시작 (예: `1.30_`)
3. **그룹 내 항목 추가** → 마지막 순번 + 1 (예: `1.13_`)
4. **더 이상 안 쓰는 파일** → 같은 레벨의 `보관_Archive` 폴더로 이동 (삭제 금지)
5. **MD 파일** → 성격에 맞게 `0_Claude_md` 하위 폴더에 보관
6. **최초_존재_기능들** → 수정/삭제 금지, 원본 보관용
7. **Claude 자동 영역(`.claude\`)은 손대지 않음** — 단, 누적된 세션·플랜은 `0_Claude_md\0.9_archive\`로 아카이브 가능

## Claude 자동 영역 (`.claude\`)

Claude Code가 자동으로 생성·관리하는 영역. 사용자가 직접 만들거나 옮기지 않지만, **어디에 무엇이 있는지는 알아야 함**.

```
C:\Users\정별\.claude\
│
├── CLAUDE.md                            # 전역 사용자 지침 (수동 편집 가능)
├── settings.local.json                  # 로컬 설정 (Claude Code가 관리)
├── .credentials.json                    # OAuth 인증 토큰 ★건드리지 말 것
│
├── projects\C--Users---\                # 본 PC(C:\Users\정별) 작업 기록
│   ├── memory\                          # auto-memory: 영구 기억 MD 파일들
│   │   ├── MEMORY.md                    #   ← 인덱스 (매 대화마다 자동 로드)
│   │   └── *.md                         #   ← 주제별 기억 파일
│   ├── *.jsonl                          # 세션별 대화 로그 (UUID 파일명)
│   └── <UUID>\                          # 세션별 보조 파일
│
├── plans\                               # 플랜 모드 산출물 (*.md)
├── sessions\                            # 활성 세션 상태
├── tasks\                               # 진행 중 task 상태
├── file-history\                        # 파일 편집 버전 스냅샷 (자동) ★건드리지 말 것
├── backups\                             # 설정 백업 ★건드리지 말 것
└── .etc\, cache\, downloads\, paste-cache\   # 기타 캐시/임시
```

### 다루는 원칙
| 폴더/파일 | 사용자 개입 | 비고 |
|-----------|-------------|------|
| `CLAUDE.md` | ✅ 직접 편집 | 전역 사용자 지침 |
| `memory\*.md` | ✅ 직접 편집/추가 가능 | Claude도 자동으로 씀 |
| `plans\*.md` | △ 완료된 플랜은 아카이브 | `0_Claude_md\0.9_archive\claude_plans\` |
| `projects\...\*.jsonl` | △ 오래된 세션은 아카이브 | `0_Claude_md\0.9_archive\claude_sessions\` |
| `file-history\`, `backups\`, `.credentials.json` | ❌ 절대 건드리지 말 것 | Claude Code 내부 메커니즘 |

### "Claude가 저장한 게 어디 있더라?" 한 줄 답
- 영구 기억 → `.claude\projects\C--Users---\memory\`
- 플랜 모드 결과 → `.claude\plans\`
- 과거 대화 → `.claude\projects\C--Users---\*.jsonl`
