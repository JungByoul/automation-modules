# 메일 수집 → 관리대장 자동화

**접수 누락 방지 + 메일 상시 확인 부담 제거**
**(부수 효과) 데이터 입력 수작업 월 8.6~14.9시간 단축 · M/M 0.05~0.1** (2026-05-26 ~ 10-20 집계)

로컬 Outlook(클래식, COM)의 받은편지함에서 특정 발신자의 승인/등록 알림 메일을 읽어
관리대장 형식의 xlsx로 자동 정리하는 스크립트.

## 하는 일

1. `메일수집_실행.bat` 실행
2. Outlook에 강제 Send/Receive를 걸어 최신 메일까지 동기화
3. 제목에 특정 키워드가 있고 지정 발신자로부터 온 메일만 필터링 (`CUTOFF` 날짜 이후만)
4. 메일 본문에서 표 형태로 박혀있는 항목(ID, 참조자, 발송시각 등)을 파싱
5. 참조자 메일주소는 `메일주소_주소록.xlsx`와 매칭해서 있으면 사람 이름으로, 없으면 메일 원문으로 기재
6. 중복 항목은 스킵하고, 접수일·접수시간 기준 정렬해서 xlsx로 저장 (실행마다 타임스탬프 파일로 스냅샷)
7. 결과 파일과 폴더를 자동으로 열어줌

## 실행 조건

- Windows + 로컬 클래식 Outlook 설치 (COM 자동화 사용, 인증/MCP 불필요)
- Python 3.x, `pip install -r requirements.txt`
- 스크립트 상단의 `BASE`, `SENDER_KEY`, `CUTOFF` 값을 실제 환경에 맞게 수정

## 자동화 효과 (세부 내역)

인수인계(2026-05-26) 전까지는 항상 수기로 진행되던 업무. 인수인계 후에도 한동안 그대로 수기로
하다가, 반복작업이 너무 많고 누락도 잦아서 이 스크립트를 만듦. 자동화 대상은 "접수 기록" 단계까지고,
이후 MDM에서 오류 확인·승인하는 단계는 여전히 사람이 함.

### 무엇을 해결했나

1. **접수 누락 방지**
   접수 1건을 놓치면 그 등록 요청이 처리되지 않고, 현업 설비 데이터와 MDM(기준정보)이 어긋난다.
   기준정보 특성상 누락 1건은 연계 시스템 전반으로 번지고, 고객 컴플레인으로도 이어진다. 수기일 때
   가장 큰 리스크가 이 누락이었고, 자동 수집·중복 제거·정렬로 구조적으로 없앴다. 즉 이 도구의
   본질은 "몇 분을 아끼느냐"가 아니라 **"틀리지 않느냐"** 다.

2. **메일 상시 확인 부담 제거**
   수기로는 접수 메일을 놓치지 않으려 하루 종일 인박스를 확인·신경 써야 했고, 그만큼 다른 업무가
   계속 끊겼다. 자동 수집은 이를 **필요할 때 클릭 한 번에 정확히**로 바꿨다.

### 수기로 할 때 1건당 거치는 단계

메일 열기·접수 확인 → 관리대장 열기·접수일 입력 → 메일 재확인·구분 판단 → Workflow ID/설비ID 복붙(표 셀 단위) →
MDM 로그인 → 변경/삭제 화면 이동 → 리스트에서 설비ID 검색·클릭 → 탭 클릭해서 담당자 이름 확인 → 관리대장에 이름 붙여넣기

| 숙련도 | 1건당 시간 |
|---|---|
| 숙련자 | 2.3분 |
| 신입(초기) | 4분 |

### 얼마나 줄었나 (2026-05-26 ~ 10-20 집계)

접수대장(`43_(261020기준)` WF 시트) **전체 접수(BULK 포함)** 기준. 영업일은 주말만 제외(공휴일 미반영).

| 항목 | 값 |
|---|---|
| 접수 건수 / 영업일 | 1,186건 / 106일 |
| 일평균 | 11.2건 |
| 1건당 수작업 | 숙련 2.3분 · 신입 4분 |
| 하루 절감 | 숙련 **25.7분** · 신입 **44.8분** |
| 월 절감(20영업일) | 숙련 **8.6시간** · 신입 **14.9시간** |
| **M/M 환산** | 숙련 **0.05** (월 1.0 영업일의 인건비 감소) · 신입 **0.1** (월 2.0 영업일의 인건비 감소) |

- **최다 요청일의 단축**: 단건이 가장 많던 날(52건, 2026-09-10)은 수기였다면 숙련 **약 2.0시간** /
  신입 **약 3.5시간**. 이게 수 초로 단축된다. (BULK까지 합치면 그날 154건.)

> M/M = 월 20영업일 × 8시간(160시간) 기준 환산. 이 평균 M/M은 "순수 데이터 입력 시간"만 잰 값으로,
> 위 1·2의 효과와는 별개다.

## 개선 예정 — 오류 처리 및 알림 (추가 구현 사양)

> **구현 상태**: 아래는 아직 구현 전인 추가 사양이다. 기존 메일 수집·Excel 생성 기능은 동작하지만,
> 이 오류 집계·로그 저장·OpenAI 요약 알림은 기존 수집 코드와의 통합 및 실제 환경 검증이 진행되지 않았다.

처리하지 못한 항목을 사용자에게 알리는 기능을 추가할 예정. 핵심은 **실행을 중단시키는 오류는 즉시 알리고, 개별 메일 문제는 저장 후 한 번에 요약**하는 것. 오류 설명을 위한 API 호출·팝업은 **실행당 최대 1회**로 구성한다. 정상 처리 시에는 OpenAI를 호출하지 않는다.

### 추가로 필요한 것

- 의존성: `openai`(오류 로그의 사용자용 설명 생성), `tkinter`(안내 팝업). `requirements.txt`에 `openai` 추가 예정.
- 파일: `error_notifier.py`(오류 로그 저장 + OpenAI 설명 요청 + 팝업), `오류로그/error_실행시각.txt`(오류 발생 실행의 상세 기록).
- 환경변수: `OPENAI_API_KEY`, `OPENAI_MODEL`(계정에서 사용 가능한 모델명). API 키·모델은 코드나 로그에 쓰지 않고 환경변수로 읽는다.

### A. 실행 중단 오류 — 즉시 알림 후 종료

대상: Outlook 연결·조회로 메일 수집을 완료하지 못한 경우 / Excel 생성·저장을 완료하지 못한 경우.

처리: ① 오류 전까지 모인 개별 메일 문제를 **포함**해 로그 저장 → ② OpenAI 1회 호출 → ③ 실패한 작업과 확인할 사항을 팝업 → ④ 종료.

### B. 개별 메일 문제 — 저장 후 요약 알림

대상: 개별 메일의 속성 읽기·본문 처리 중 예외 / `if not eq:`의 설비목록 추출 실패.

루프 동안에는 문제를 `issues` 목록에 누적만 하고 OpenAI·팝업을 호출하지 않는다. 설비목록 추출 실패는 기존처럼 결과에 `설비목록 파싱실패` 행을 남기고 요약 집계에도 포함한다. Excel 저장 완료 후 ① 누적 문제를 TXT 로그 1건으로 저장 → ② OpenAI 1회 호출 → ③ 저장 결과와 문제 유형별 건수를 요약 팝업.

| 실행 결과 | 처리 |
|---|---|
| 메일 수집 자체 실패 | 즉시 알림 1회 후 종료 |
| Excel 저장 실패 | 기존에 모인 문제까지 합쳐 즉시 알림 1회 후 종료 |
| Excel 저장 성공 + 개별 메일 문제 | 저장 후 요약 알림 1회 |
| 정상 처리 | OpenAI 호출·팝업 없음 |

주소록 로드 실패와 결과 파일·폴더 자동 열기 실패는 기존 콘솔 안내를 유지한다. Outlook 동기화 실패는 최신 메일 미반영 가능성을 **경고로 기록**하되 단독 팝업은 띄우지 않는다.

### 집계·로그 작성 기준

- **실행 단위 `issues` 목록**을 `main()`에서 만들고 수집 함수가 여기에 누적. 수집 중단·저장 실패 시에도 그전에 모인 문제를 최종 로그에 함께 남긴다.
- **메일 식별정보 초기화**: 반복 시작마다 `subj = ""`, `recv_d = None`으로 초기화하고 실행 내 항목번호를 부여한다. 접수일·제목을 읽다 실패해도 **이전 메일 정보가 로그에 남지 않게** 한다.
- **집계 표현**: "메일 처리 예외 N건 / 설비목록 추출 실패 M건 / Excel 저장 완료·실패"를 구분 표기. `matched` 증가 전에 예외가 날 수 있으므로 "총 matched건 중 N건 실패"로 쓰지 않는다. 한 메일의 설비 일부가 결과에 들어간 뒤 오류가 날 수 있으므로, 예외 건수를 누락 설비 행 수로 환산하지 않고 "일부 설비 정보가 누락됐을 수 있음"으로 안내한다.
- **로그에 남길 정보**: 발생시각 / 작업 단계 / 메일 항목번호 / 확인 가능한 접수일·제목 / 오류 종류·상세 / 확인된 처리 영향 / Excel 저장 완료 여부 / 메일 예외 건수 / 설비목록 추출 실패 건수. 상세 식별정보는 **로컬 로그에만** 보관하고, OpenAI에는 오류 유형·코드·건수·작업 단계·처리 영향 요약만 전달한다.

### OpenAI 설명 및 팝업 규칙

Python이 "실패한 작업과 처리 영향"을 확정하고, OpenAI는 그 정보를 쉬운 문장으로 설명한다. 프롬프트 기준: 기록된 처리 영향을 바꾸거나 확대하지 않기 / 원인을 확정할 수 없으면 가능성으로 표현 / 사용자가 확인할 사항 포함 / 쉬운 한국어 존댓말 3문장 이내 / 파일을 직접 검사·수정했다고 표현하지 않기. 팝업은 Python이 확인한 결과를 먼저, OpenAI 설명을 "참고"로 덧붙인다.

요약 팝업 예시 (문구·건수는 형식 예시):

```text
메일 수집 결과 확인

Excel 파일 저장을 완료했습니다.
메일 처리 예외 3건, 설비목록 추출 실패 2건이 있습니다.
일부 설비 정보가 누락됐을 수 있습니다.

AI 설명(참고):
일부 메일의 정보를 읽거나 설비 목록을 추출하지 못했습니다.
상세 로그에 기록된 메일과 결과 파일의 파싱실패 표시를 확인해 주세요.

상세 로그: 오류로그/error_실행시각.txt
```

알림 기능 자체의 실패: API 타임아웃 15초 / 자동 재시도 0회 / API 실패 시 Python 기본 오류 정보로 팝업 / 로그 저장 실패 시 콘솔 출력 후 알림 시도 / 팝업 실패 시 콘솔 출력. 알림 실패가 기존 수집을 추가로 중단시키거나 재귀 호출되지 않게 한다.

### 통합 후 확인할 항목

- 정상 처리 시 기존 Excel 결과가 생성되고 API·팝업이 실행되지 않는지
- 여러 메일 문제 시 요약 알림이 1회만 실행되는지
- 설비목록 추출 실패가 Excel 표시 행과 요약 집계에 모두 반영되는지
- 접수일·제목 읽기 실패 시 이전 메일 정보가 로그에 남지 않는지
- 수집·저장 실패 시 앞서 모인 문제도 같은 로그에 포함되는지
- API 연결 실패 시 기본 오류 안내가 표시되는지
- 팝업에서 Excel 저장 성공·실패를 정확히 구분하는지
