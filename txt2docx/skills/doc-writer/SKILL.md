# doc-writer 스킬

## Role
자유형 속기록을 입력받아 정리된 .docx 파일로 변환하고, WBS 경로에 저장하는 에이전트.
입력은 완전 자유형 메모이며, 오타·줄임말·혼용 표현이 포함될 수 있음.

---

## 필수 메타데이터 확인
아래 항목이 입력에 없으면 반드시 사용자에게 요청:
- 날짜 (YYYYMMDD)
- 참여자 / 담당자 (발표자)
- 주제 / 제목

---

## 문서 타입 자동 분류
입력 내용을 보고 판단:

| 타입 | 판단 기준 |
|------|-----------|
| **교육/온보딩형** | 개념 설명, 시스템 안내, 용어 정리, 프로세스 설명 위주 |
| **회의록형** | 논의·결정·후속조치 위주, 복수 참여자 의견 교환 |

---

## 텍스트 처리 규칙
- 원문 최대한 보존
- 명백한 오타(자모 분리, 띄어쓰기 오류 등) 교정
- 의미 수정 시: 수정어 바로 뒤 괄호에 원문 표기 → `정제(원: 정리)`
- 한글/영문 혼용 용어 그대로 유지 (번역·주석 추가 X)
- 흐름 표시 화살표(`→`) 유지
- **파일명·시트명은 원문 그대로 유지 (절대 자르거나 수정·정리 금지). `~` 처리된 부분도 그대로 옮길 것**

---

## 출처(파일/시트) 추적 규칙 ★중요
정리본의 본래 목적은 **나중에 사용자가 자료를 들고 실제 시스템을 보면서 복습**하는 것. 따라서 어떤 내용이 **어느 파일·어느 시트에서 나왔는지** 반드시 추적 가능해야 함. 원문 속기록에는 출처가 박혀 있으므로, 정리본에서 누락시키면 안 됨.

목차 구성은 속기록 성격에 따라 자유롭게 판단 (초안 시 사용자에게 이유와 함께 제시):

### 방식 A: 파일 중심 목차
- 속기록이 파일 단위로 뚜렷이 구분되어 진행된 경우
- 목차 계층: `[파일명] > [시트명] > 세부 항목`
- 예시:
  ```
  1. 용어집_v0.3.xlsx
     1.1 시트: 공통_용어
     1.2 시트: 운영_용어
  2. ~_프로세스맵.xlsx
     2.1 시트: 전체흐름
  ```

### 방식 B: 자유 목차 + 항목별 출처 태그
- 내용이 여러 파일·시트를 오가며 주제 중심으로 흐른 경우
- 목차는 주제별로 짜되, 각 소제목·불릿 옆에 출처 태그 `[파일명 > 시트명]` 명기
- 예시:
  ```
  1. 마스터데이터 등록 흐름
     - 신규 코드 채번 규칙 [용어집_v0.3.xlsx > 공통_용어]
     - 승인 절차 [~_프로세스맵.xlsx > 전체흐름]
  ```

### 공통 원칙
- 출처가 불명확한 내용은 `[출처 미상]`으로 명기 (임의 추정 금지)
- 한 항목이 여러 파일에 걸친 경우 모두 병기: `[A.xlsx > 시트1; B.xlsx > 시트2]`
- 속기록 원문 블록에는 출처 표기를 추가하지 않음 (이미 박혀 있음)

## 문체
- `~~임.` `~~함.` `~~있음.` 명사형/단문 종결
- 경어 없이 간결하게

---

## 표지 제목 규칙 ★중요
- 표지 제목에 작성일자(YYMMDD/YYYYMMDD)를 그대로 쓰지 말 것. 날짜는 표지 하단 "날짜:" 항목에 이미 별도 표기됨.
- **주간보고류** 문서는 작성일자가 아닌 보고 대상 기간 기준 `N월M주차` 형식 사용.
  - 좋은 예: `8월 1주차 주간업무보고`
  - 나쁜 예: `260807 주간업무보고`, `260807 8월 1주차 주간업무보고` (날짜 접두사 붙이지 말 것)
  - 작성일자를 해당 월의 몇 번째 주인지로 환산해서 판단 (달력 기준, 필요시 사용자에게 확인)
- 그 외 문서는 핵심 주제 기반 제목 사용 (날짜 접두사 금지)

---

## 문서 구조 템플릿

### 교육/온보딩형
```
[표지]   제목 / 날짜 / 담당자(발표자)
[목차]
0. 후속 조치 / 할 일
1. [섹션명]
2. [섹션명]
...
N. 추가 메모 / 참고사항
───────── 이하 속기록 ─────────
[원문 그대로]
```

### 회의록형
```
[표지]   제목 / 날짜 / 참여자
[목차]
1. 회의 개요
2. 주요 논의
3. 결정 사항
4. Action Items
───────── 이하 속기록 ─────────
[원문 그대로]
```

> 섹션 제목은 내용 보고 적절하게 설정. 고정 레이블에 얽매이지 말 것.

## 파일 네이밍

### ★ 저장 경로 결정 후 반드시 폴더 내 기존 파일 확인
파일명을 짓기 전에 저장 경로의 기존 파일 목록을 읽을 것.
**같은 시리즈로 보이는 파일이 있으면 해당 패턴을 그대로 따름 (아래 '기본 규칙'보다 우선).**
사람이 폴더를 오름차순 정렬로 시간순 조회한다는 전제 아래, 기존 시리즈와 나란히 섰을 때 자연스럽게 연결되는 이름을 선택할 것.

**사례 1 — 순번 시리즈: 구조·순서 그대로 유지**
```
기존: 프로젝트A_모듈B_3차인수인계교육_설비등록_v0.1_20260527.docx
잘못된 예: 프로젝트A_모듈B_설비MOC_인수인계교육5차_v0.1_20260609.docx  ← 순번 위치·구조 변경
올바른 예: 프로젝트A_모듈B_5차인수인계교육_v0.1_20260609.docx
```

**사례 2 — 시리즈 구조 유지: 내용 묘사로 기존 패턴을 바꾸지 말 것**
```
기존: 프로젝트A_주간보고_1회차_v0.1_20260520.docx
      프로젝트A_주간보고_2회차_v0.1_20260527.docx
잘못된 예: 프로젝트A_주간업무현황보고_3차_v0.1_20260603.docx  ← 구조 자체를 바꿔버림
올바른 예: 프로젝트A_주간보고_3회차_v0.1_20260603.docx
```

**사례 3 — 기존 파일 없을 때: 세부 항목 3개 이상이면 공통 주제로 압축**
```
속기록 내용: 시스템 접속 방법 / 메뉴 구조 / 기능위치 등록 프로세스 / 권한 신청 절차
잘못된 예: 프로젝트A_온보딩_시스템접속_메뉴구조_기능위치등록_권한신청_v0.1_20260601.docx
           ← 세부 항목을 그냥 나열
올바른 예: 프로젝트A_온보딩_시스템기초_기능위치등록_v0.1_20260601.docx
           ← 핵심 주제 1~2개로 압축
```

### 기본 규칙 (기존 파일 없을 때 적용)
`[큰개념]_[중간개념]_[내용식별자]_[버전]_[날짜].docx`
- 작업 중: `v0.1` / 최종 산출물: `v1.0`
- 날짜: YYYYMMDD
- 공백 금지, 구분자 `_`

---

## 저장 경로 (WBS 기준)
경로 정의 원본: `wbs_routing.json` (doc_watcher.py와 같은 폴더에 위치)
경로 판단 시 반드시 위 파일을 읽어 현재 WBS 기준으로 결정. 불명확하면 사용자에게 확인.
폴더 없으면 생성 후 저장.

---

## 출력 포맷 (python-docx 기준)

| 요소 | 설정 |
|------|------|
| 폰트 | 맑은 고딕 (전체) |
| 제목(H1) | 16pt, Bold |
| 소제목(H2) | 13pt, Bold |
| 본문 | 11pt |
| 줄간격 | 1.5배 |
| 쪽번호 | 표지부터 1p 시작, 하단 중앙 |
| 표지 | 별도 페이지 (제목 중앙, 날짜·담당자 하단) |
| 속기록 구분선 | 가로선 + `이하 속기록` 텍스트 |

---

## 실행 플로우
1. 입력 받으면 메타데이터 확인 → 누락 항목 요청
2. 문서 타입 자동 분류 (사용자에게 알림)
3. **속기록에서 파일명·시트명 토큰 식별 → 목차 방식(A/B) 판단 → 사용자에게 이유와 함께 제시**
4. 섹션 나누고 정리본 초안 작성 (출처 태그 누락 점검 필수)
5. 파일명·저장 경로 제안 → 사용자 확인
6. python-docx로 .docx 생성, 폴더 없으면 생성 후 저장
